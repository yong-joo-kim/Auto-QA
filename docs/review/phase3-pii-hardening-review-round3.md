## 4. 발견 사항

### H-1(R3) (High, 차단) `group.length > 8` 제약이 Phase 1 마스킹 레이아웃 4-12 / 12-4를 평문으로 되돌림

- 위치: `packages/pii-mask/src/mask.ts:206`
  `if (groups.some((group) => group.length < 2 || group.length > 8)) return match;`
- 원인: Phase 1 카드 규칙은 `\b\d{4}[-\s]?\d{4}[-\s]?\d{4}[-\s]?\d{4}\b`로, 16자리를 4자리 경계(4/8/12)에서 **구분자를 선택적으로** 넣은 **8가지 레이아웃 전부**를 마스킹한다(무구분, 4-12, 8-8, 12-4, 4-4-8, 4-8-4, 8-4-4, 4-4-4-4). 이번 라운드에 추가된 그룹 길이 **상한 8**은 이 중 **4-12와 12-4**를 배제한다. 2차 리뷰 시점 코드(`digitCount===16` + 구분자 존재)에서는 마스킹되던 케이스이므로 **이번 수정이 새로 만든 손실**이다.
- 실측(동일 입력, Phase 1 = `[카드번호]` / Phase 3 = 평문). 구분자 5종(하이픈/스페이스/TAB/NBSP/전각공백) × 2레이아웃 = **10조합**:

| 입력 | Phase 1 | Phase 3(현재) |
| ---- | ------- | ------------- |
| `카드 4012-888888888886 입니다` | `카드 [카드번호] 입니다` | 원문 평문 |
| `카드 401288888888-8886 입니다` | `카드 [카드번호] 입니다` | 원문 평문 |
| `카드 4012 888888888886 입니다`(SPACE/TAB/NBSP/U+3000 동일) | `카드 [카드번호] 입니다` | 원문 평문 |

- 영향: 1차 H-1·2차 H-1(R2)와 **완전히 동일한 유출 유형**이다(Phase 1 마스킹 → Phase 3 `maskedText` 평문 DB 영구 저장 + LLM 전송, 원문 미저장 정책상 사후 재마스킹 불가). 다만 4-12/12-4 표기의 실사용 빈도는 TAB·NBSP보다 낮다고 판단되므로 Critical이 아닌 High로 본다. AC-R-1은 조건 없는 차단 기준(DoD §10.2)이라 등급과 무관하게 Phase 3 완료를 막는다.
- 근본 원인(프로세스): 상한 8은 **L-2(R2)(유출 아님, 종류 오귀속 Low)** 를 해소하려고 도입됐는데, 그 대가로 **유출 방향(High)** 손실을 만들었다. 우선순위가 역전된 교환이다. 또한 코퍼스가 "리뷰가 보고한 개별 케이스"만 고정하고 **레이아웃 공간 전체를 고정하지 않아** 3라운드 연속 같은 계열 결함이 새 위치에서 재발했다.

### L-1(R3) (Low) 부분 구분자 규칙이 "공백 1문자"만 허용 — 4-4-4-4 규칙과 비대칭

- 위치: `mask.ts:171` `CARD_PARTIAL_SEP_PATTERN = /\b\d(?:\d|[-.](?=\d)|[^\S\r\n](?=\d))*\d\b/g`
- `[^\S\r\n](?=\d)`는 공백을 **1문자만** 허용하므로 `카드번호 40128888  8888 8886`(공백 2개), `4012 -8888-88888886`(공백+하이픈 혼용)은 미탐이다. 반면 4-4-4-4 규칙은 `[^\S\r\n]+`라 연속 공백을 처리한다(`4012  8888  8888  8886` → 마스킹). Phase 1도 `[-\s]?`로 1문자만 허용했으므로 **회귀는 아니다**(차단 아님).
- 권고: `(?:[^\S\r\n]|[-.])+(?=\d)` 형태로 통일하거나, 유지한다면 `KNOWN_FALSE_NEGATIVE_CASES`에 "부분 구분자 규칙은 구분자 1문자만 허용" 1행을 등재.

### 확인만 한 항목(신규 결함 아님)

- **ReDoS(NFR-3.1) 정적 점검**: `CARD_PARTIAL_SEP_PATTERN`은 대안 3개의 선행 문자 집합(숫자 / `[-.]` / 공백류)이 서로 배타적이고 중첩 수량자가 없으며 `(?=\d)`가 구분자 꼬리 소비를 막는다 → 모호성 없음. `CARD_GROUP_SPLIT_PATTERN`·`CARD_DATE_LIKE_PATTERN`은 고정 길이/단일 수량자이며 **둘 다 non-global**이라 `test`/`split` 재사용 시 `lastIndex` 상태 버그도 없다. 스케일링 실측도 전부 선형 → NFR-3.1 충족.
- **무구분 16자리 Luhn 탈락(`1234567890123456` 등) 미탐**: Phase 1 대비 손실이지만 요구사항 FR-2.2가 명시적으로 규정한 정책(§7 `고객번호 0212345678901234` 원문 보존)이며 `KNOWN_FALSE_NEGATIVE_CASES`에 등재됨 → 회귀 아님.
- **PII 경로**: `mask.ts` 변경분에 I/O·로그·throw·`Date`/`Math.random` 없음. 공개 API(`maskPii`) 시그니처 불변, 반환값에 원문 조각·위치·길이 없음. API/Web 호출부 무변경(tsc 0 error).
